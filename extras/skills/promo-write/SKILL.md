# promo-write — 홍보 문구는 쓰고, 바로 퇴고하고, 묶어서 한 번 더 본다

근거: `docs/experiments/2026-11-25-promo-copy.md` (9개 조건 × 3주제, 블라인드 순위).
요지 — **이미 쓴 AI 초안을 나중에 윤문하는 것보다, 사실 목록을 쥔 채 쓰고 바로 퇴고하는 쪽이 압도적으로 낫다.**
윤문기는 원래 자료를 모르니 초안이 지어낸 사실("몇 시간씩", "업무 시간을 줄여 주는")을 걸러 내지 못한다.

| 순위 | 조건 | 평균 순위 |
|---|---|---|
| 1 | 브리프+지침으로 작성 → **같은 작성자가 자가 퇴고** | 1.3 |
| 2 | 브리프+지침으로 작성 → **출시 전 묶음 퇴고**(3편을 한 에이전트가 함께) | 1.7 |
| 3 | 브리프+지침으로 작성 → 편마다 별도 퇴고 에이전트 | 3.3 |
| 4~ | 이미 쓴 초안 윤문(지침 스킬 4.7 / 별도 퇴고 5.3 / 정규식 힌트 6.3 / 원래 스킬 7.7) | |
| — | 지침만 주고 작성(퇴고 없음) | 6.0 — 지침을 줘도 첫 작성엔 버릇이 그대로 나온다 |

## 단계

### 1. 브리프 — 사실 목록부터
쓰기 전에 넣을 사실을 줄 단위로 적는다: 대상·일정·가격·혜택·조건·신청 방법·수치.
**목록에 없는 사실은 쓰지 않는다.** 분량이 모자라도 채우지 않는다(실측: 분량을 채우려고 넣은 문장이 감점·사실 의심을 받았다).

### 2. 작성 — 지침을 읽고 쓴다
지침: `skills/humanize-korean/references/quick-rules.footer.md` 의 「장르 지침 — 홍보·안내·모집 문구」 8항목.
판단 기준 하나 — **지워도 독자가 잃는 정보가 없는 문장은 AI 티다.**

### 3. 자가 퇴고 — 같은 작성자가 곧바로 (필수)
쓴 글을 다시 읽고 8항목으로 퇴고한다. 같은 대화 안에서 하면 된다(서브에이전트 불필요).
확인: 브리프 사실이 전부 들어갔나, 없는 사실을 지어내지 않았나.

### 4. 출시 전 묶음 퇴고 — 여러 편을 같이 낼 때
같은 날·같은 채널에 여러 편이 나가면, 다 쓴 뒤 **한 에이전트에 전부 묶어서** 한 번 더 본다.
- 먼저 편 사이에 되풀이되는 말버릇을 목록으로 뽑는다(같은 시작·같은 맺음·같은 어미·같은 뼈대). 한 편만 보면 안 보인다.
  실측에서 3편 묶음 퇴고가 찾아낸 것: 세 편 모두 행동 권유로 맺음, 「~해 드려요」 2~4회씩, 「직접 확인해 보세요」류, 안심 문구 하나씩, 「요약 → 목록 → 신청 안내」 같은 뼈대.
- 편마다 시작과 맺음을 다르게 한다.
- 비용도 싸다: 편마다 퇴고 에이전트를 띄우는 것(3회)보다 묶음 1회가 순위도 높았다(3.3 → 1.7).

### 5. 사실 대조
브리프의 각 줄이 결과에 있는지 확인한다. 퇴고가 사실을 「과장」으로 오인해 지우는 일이 실제로 있었다("몇 분 만에"를 근거 없는 과장으로 보고 삭제). 브리프에 있는 표현은 과장 판정 대상이 아니다.

## 하지 않는 것
- 정규식 목록으로 표현을 일괄 치환하지 않는다 — 판단은 모델이 문맥으로 한다. 정규식은 결과를 **재는** 데만 쓴다(`extras/promo-bench/score.py`).
- 사람 홍보문에도 위 표현이 가끔 있다(사람 글 600자 창 기준 0.3~3%). 한 번 쓰인 것까지 다 지우지 않는다.
- 너무 깎아서 건조한 공지문으로 만들지 않는다 — 블라인드 평가는 「읽고 싶은가」도 본다.
